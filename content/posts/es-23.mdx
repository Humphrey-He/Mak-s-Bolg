# ES 资料与工具导航

> 学 ES 最容易掉进两个坑：只背 API，不理解 Lucene 和分布式原理；只看原理，不会在 Kibana Dev Tools 里把问题查出来。这篇按学习路径和生产工具分类整理，方便后续持续更新。

## 1. 问题背景

Elasticsearch 的知识面很宽：全文检索、分词、倒排索引、分布式一致性、JVM、Linux、日志平台、可观测性、备份迁移、权限安全、云原生部署。资料很多，但质量参差不齐，而且不同版本差异明显。

建议学习时坚持三条原则：

- 先看官方文档确认当前版本语义，再看社区文章理解经验。
- 每个 API 都在 Dev Tools 里跑一次，不把“看过”当成“会了”。
- 把资料按任务组织：建模、查询、优化、排障、迁移，而不是按链接收藏。

## 2. 核心概念

### 2.1 资料分类

| 类别 | 解决的问题 | 推荐使用方式 |
|---|---|---|
| 官方文档 | API、版本行为、兼容性 | 查准确语义和参数 |
| 官方博客/指南 | 最佳实践、架构方案 | 学生产思路 |
| Lucene 资料 | 倒排索引、评分、segment | 理解 ES 底层 |
| 客户端文档 | Java/Python/JS/Go 接入 | 写业务代码 |
| 工具文档 | Kibana、Rally、Curator、Exporter | 调试、压测、运维 |
| 社区文章 | 案例复盘、经验总结 | 对照验证，不盲信 |
| 源码/Issue | 边界行为、疑难问题 | 深入排查 |

### 2.2 学习路径

```mermaid
flowchart LR
  A["入门 API"] --> B["mapping / analysis"]
  B --> C["Query DSL / aggregation"]
  C --> D["Lucene 原理"]
  D --> E["写入和查询链路"]
  E --> F["性能优化与排障"]
  F --> G["ILM / SLM / 安全 / 迁移"]
  G --> H["搜索相关性和业务建模"]
```

不要一开始就陷入所有 API 的细节。真正形成生产能力的关键是：知道某个设计会带来什么读写成本，知道问题发生时从哪里取证。

## 3. 资料分类导航

### 3.1 官方入口

- [Elasticsearch Reference](https://www.elastic.co/guide/en/elasticsearch/reference/current/index.html)：最重要的参考入口，API、settings、mapping、query DSL 都从这里查。
- [Elastic Docs](https://www.elastic.co/docs)：Elastic 全产品文档入口，适合查部署、管理、迁移和云服务。
- [Elastic Blog](https://www.elastic.co/blog)：官方博客，适合看搜索、可观测性、性能和新特性文章。
- [Elastic Discuss](https://discuss.elastic.co)：官方社区问答，很多异常栈和边界问题能搜到历史讨论。
- [Elastic GitHub](https://github.com/elastic/elasticsearch)：源码、Issue、Release note 入口。

### 3.2 入门与 API

- [REST APIs](https://www.elastic.co/docs/api/doc/elasticsearch)：按 endpoint 查请求参数和响应结构。
- [Search your data](https://www.elastic.co/docs/solutions/search)：学习查询语义、相关性和搜索应用。
- [Mapping](https://www.elastic.co/guide/en/elasticsearch/reference/current/mapping.html)：字段类型、dynamic mapping、runtime fields。
- [Analysis](https://www.elastic.co/guide/en/elasticsearch/reference/current/analysis.html)：分词器、char filter、tokenizer、token filter。
- [Query DSL](https://www.elastic.co/guide/en/elasticsearch/reference/current/query-dsl.html)：所有查询能力的核心入口。
- [Aggregations](https://www.elastic.co/guide/en/elasticsearch/reference/current/search-aggregations.html)：bucket、metric、pipeline 聚合入口。

实践建议：每学一个 API，就创建一个最小索引、写入 5-10 条文档、跑正反两个查询，并观察 explain/profile。

```http
GET products/_search
{
  "explain": true,
  "query": {
    "match": {
      "title": "wireless headphone"
    }
  }
}
```

### 3.3 建模与中文检索

建模资料重点看这些主题：

- `text` 与 `keyword` 的边界。
- `object`、`nested`、`flattened` 的取舍。
- `date`、numeric、`scaled_float` 的存储和聚合。
- `dense_vector` 和 kNN 的适用场景。
- analyzer、normalizer、synonym、search_analyzer。
- 中文分词、拼音、同义词、停用词、繁简转换。

常用插件和项目：

- [analysis-icu](https://www.elastic.co/guide/en/elasticsearch/plugins/current/analysis-icu.html)：Unicode、大小写、折叠、国际化分析。
- [IK Analysis for Elasticsearch](https://github.com/infinilabs/analysis-ik)：社区常用中文分词插件，使用前要确认版本匹配。
- [pinyin analysis plugin](https://github.com/infinilabs/analysis-pinyin)：中文拼音检索场景常用，注意召回噪声。

中文检索实践提醒：

- 不要只靠一个字段解决所有搜索体验，可以建立 `title`、`title.keyword`、`title.pinyin`、`title.search_as_you_type` 等多字段。
- 同义词更新要设计发布流程，避免线上搜索行为突然变化。
- 拼音召回要配合权重和业务规则，否则短拼音会带来大量误召回。

### 3.4 性能优化与压测

- [Tune for indexing speed](https://www.elastic.co/guide/en/elasticsearch/reference/current/tune-for-indexing-speed.html)：写入优化清单。
- [Tune for search speed](https://www.elastic.co/guide/en/elasticsearch/reference/current/tune-for-search-speed.html/)：查询优化清单。
- [Size your shards](https://www.elastic.co/guide/en/elasticsearch/reference/current/size-your-shards.html)：分片规划。
- [Elasticsearch performance optimizations](https://www.elastic.co/docs/deploy-manage/production-guidance/optimize-performance)：性能优化官方入口。
- [Rally](https://esrally.readthedocs.io)：Elastic 官方压测工具，适合容量评估和版本对比。

Rally 示例：

```bash
esrally race --track=geonames --target-hosts=127.0.0.1:9200 --pipeline=benchmark-only
```

生产排障常用 API：

```http
GET _cluster/health
GET _cat/nodes?v
GET _cat/shards?v
GET _nodes/hot_threads
GET _nodes/stats/jvm,indices,thread_pool,breaker
GET _tasks?detailed=true
```

### 3.5 Kibana 与可观测性

- [Kibana Guide](https://www.elastic.co/guide/en/kibana/current/index.html)：Kibana 文档入口。
- Dev Tools：调试 REST API 和 DSL。
- Discover：查日志和样本文档。
- Lens/Dashboard：做可视化看板。
- Stack Monitoring：观察 ES、Kibana、Logstash、Beats。
- Search Profiler：分析查询耗时。
- APM：应用调用链和 ES 请求关联。

Search Profiler 适合回答：

- 慢在 term 查询、match 查询还是聚合。
- 哪个 shard 慢。
- rewrite 和 collect 阶段耗时如何。
- 是否需要改 mapping 或查询结构。

### 3.6 客户端与业务接入

官方客户端优先：

- [Java API Client](https://www.elastic.co/guide/en/elasticsearch/client/java-api-client/current/index.html)
- [Python Client](https://elasticsearch-py.readthedocs.io/)
- [JavaScript Client](https://www.elastic.co/guide/en/elasticsearch/client/javascript-api/current/index.html)
- [Go Client](https://www.elastic.co/guide/en/elasticsearch/client/go-api/current/index.html)

业务接入建议：

- 不要在业务代码里拼字符串 DSL，优先用结构化对象。
- 给所有查询设置 timeout。
- 给 bulk 写入设置重试、退避和失败记录。
- 把索引名通过 alias 或配置管理，不要硬编码物理索引。
- 客户端连接池、认证、TLS、压缩都要按生产环境配置。

Java 客户端查询思路示例：

```java
SearchResponse<ProductDoc> response = esClient.search(s -> s
    .index("products_read")
    .query(q -> q
        .bool(b -> b
            .must(m -> m.match(mm -> mm.field("title").query("无线耳机")))
            .filter(f -> f.term(t -> t.field("status").value("online")))
        )
    )
    .size(20),
    ProductDoc.class
);
```

### 3.7 运维、备份与迁移

- [Snapshot and restore](https://www.elastic.co/guide/en/elasticsearch/reference/current/snapshot-restore.html)：快照恢复总入口。
- [Create, monitor and delete snapshots](https://www.elastic.co/guide/en/elasticsearch/reference/current/snapshots-take-snapshot.html)：手动快照和 SLM。
- [Reindex documents](https://www.elastic.co/guide/en/elasticsearch/reference/current/docs-reindex.html/)：重建索引和 remote reindex。
- [Migrate your Elasticsearch data](https://www.elastic.co/docs/manage-data/migrate)：迁移官方入口。
- [Index lifecycle management](https://www.elastic.co/guide/en/elasticsearch/reference/current/index-lifecycle-management.html)：ILM 和冷热生命周期。

运维工具：

- Curator：老牌索引管理工具。新项目优先考虑 ILM/SLM，Curator 更适合遗留集群补齐自动化。
- Elastic Cloud / ECK：云上托管和 Kubernetes Operator。
- Prometheus exporters：如果公司统一 Prometheus 体系，可接入 exporter。
- 自研巡检脚本：检查 shard 数、磁盘水位、模板漂移、慢日志、未分配分片。

巡检脚本最小检查项：

```bash
curl -s "$ES/_cluster/health?pretty"
curl -s "$ES/_cat/indices?v&s=store.size:desc"
curl -s "$ES/_cat/shards?v&s=state,index"
curl -s "$ES/_cat/thread_pool/search,write?v"
```

### 3.8 安全与权限

学习重点：

- TLS、用户、角色、API key。
- index privilege、cluster privilege。
- Kibana space 和 saved object 权限。
- 审计日志。
- 跨集群访问的认证和最小权限。

生产建议：

- 不要共享 `elastic` 超级用户给业务系统。
- 每个服务使用独立 API key 或最小权限用户。
- remote reindex 用户只给 `monitor` cluster privilege 和源索引 `read` 权限。
- 快照仓库权限单独管理，避免误删和越权恢复。

### 3.9 OpenSearch 对比资料

OpenSearch 源自 Elasticsearch 7.10.2 之后的分支。选型时需要关注：

- 许可证和商业策略。
- API 兼容性。
- 插件生态。
- 安全、SQL、向量检索、Dashboard 能力。
- 现有团队经验和云厂商支持。

如果公司已经大量使用 Elastic Stack 的 Kibana、Fleet、APM、安全能力，迁移要谨慎评估生态差异。若主要使用基础搜索和日志分析，也要做插件、客户端、DSL 和运维工具兼容性验证。

## 4. 实践方法：一条可执行学习路线

### 阶段一：跑通最小闭环

目标：能独立完成安装、建索引、写入、查询、聚合。

练习：

```http
PUT blog_posts
{
  "mappings": {
    "properties": {
      "title": { "type": "text", "fields": { "keyword": { "type": "keyword" } } },
      "tags": { "type": "keyword" },
      "views": { "type": "integer" },
      "created_at": { "type": "date" }
    }
  }
}
```

```http
POST blog_posts/_doc/1
{
  "title": "Elasticsearch 查询入门",
  "tags": ["es", "search"],
  "views": 1024,
  "created_at": "2026-05-25"
}
```

### 阶段二：掌握建模

目标：能解释每个字段为什么这样设计。

练习：

- 为商品搜索设计 mapping。
- 为日志检索设计 data stream template。
- 对比 `object` 和 `nested` 查询结果。
- 用 `_analyze` 调试中文分词。

```http
POST _analyze
{
  "analyzer": "standard",
  "text": "无线降噪耳机"
}
```

### 阶段三：深入查询与聚合

目标：能写出可解释、可控成本的 DSL。

练习：

- bool 查询组合。
- match/match_phrase/multi_match 对比。
- terms/date_histogram/cardinality 聚合。
- search_after + PIT 深分页替代。
- Profile API 分析查询耗时。

### 阶段四：理解原理

目标：能把 refresh、flush、merge、translog、segment、doc_values 讲清楚。

练习：

- 写入后马上查询，观察 refresh 可见性。
- 调整 refresh_interval 后观察 segment。
- 删除大量文档后观察 force merge。
- 对排序/聚合字段比较 doc_values 开关影响。

### 阶段五：生产治理

目标：能设计一个可上线的 ES 服务。

练习：

- 设计索引模板和 ILM。
- 做一次 bulk 写入压测。
- 开启慢日志并分析一条慢查询。
- 建立 snapshot repository 和 SLM。
- 完成一次 restore 演练。
- 用 alias 做零停机 reindex。

## 5. 工程取舍

### 5.1 官方文档 vs 社区文章

官方文档准确，但不总是告诉你业务上怎么取舍。社区文章有经验，但可能版本过旧。我的建议是：参数语义以官方文档为准，工程方案多看几篇社区实践再自己压测。

### 5.2 API 手册 vs 项目实战

只看 API 很难形成判断力。最好用一个贯穿项目练习，比如：

- 商品搜索：相关性、过滤、排序、聚合、suggest。
- 日志平台：data stream、ILM、字段治理、慢查询、快照。
- 订单风控：租户隔离、routing、时间范围、权限和审计。

### 5.3 新特性 vs 稳定性

ES 新版本会持续加入 ES|QL、向量检索、serverless、data stream、downsample 等能力。生产上不要因为新而使用，也不要因为陌生而拒绝。判断标准是：是否能降低复杂度，是否能被监控，是否有回滚方案。

## 6. 排障资料速查

### 6.1 查询慢

- 查慢日志。
- 用 Search Profiler / Profile API。
- 查命中 shard 数。
- 查 fetch 字段和高亮。
- 查 search thread pool rejected。

```http
GET _cat/thread_pool/search?v
GET _nodes/hot_threads
```

### 6.2 写入慢

- 查 bulk 响应错误。
- 查 write/bulk 线程池。
- 查 ingest pipeline stats。
- 查 refresh/merge stats。
- 查磁盘延迟和水位。

```http
GET _nodes/stats/indices/indexing,indices/refresh,indices/merges
GET _nodes/stats/ingest
```

### 6.3 分片异常

- 查 unassigned。
- 查 allocation explain。
- 查磁盘水位。
- 查索引模板副本数和 allocation filtering。

```http
GET _cluster/allocation/explain
GET _cat/shards?v&s=state
```

### 6.4 备份失败

- 查 repository verify。
- 查 `_snapshot/repo/_current`。
- 查 SLM stats。
- 查对象存储权限和网络。

```http
POST _snapshot/prod_s3_repo/_verify
GET _slm/stats
```

## 7. 小结

- ES 学习要按任务组织资料：建模、查询、原理、优化、迁移。
- 官方文档负责准确性，社区文章负责案例启发，最终方案必须压测。
- Dev Tools、Profile API、慢日志、Rally 是从入门到生产都绕不开的工具。
- 中文检索、相关性和聚合性能都高度依赖 mapping，别把建模当成后置工作。
- 生产 ES 能力的标志不是会写 DSL，而是能设计边界、监控风险、恢复故障。

## 8. 推荐阅读顺序

1. Elasticsearch Reference 的 mapping、analysis、query DSL、aggregations。
2. 本系列前五个模块：基础概念、安装入门、索引建模、查询聚合、核心原理。
3. 官方性能文档：indexing、search、shards。
4. 官方 snapshot/restore、reindex、ILM/SLM 文档。
5. Lucene 相关性和倒排索引资料。
6. 大厂实践和社区故障复盘。
7. 根据业务方向深入：商品搜索、日志平台、向量检索、可观测性。
