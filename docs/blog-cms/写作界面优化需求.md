# 博客 CMS 编辑器优化开发需求文档

## 1. 背景与目标

当前自研 Blog CMS 已具备文章创建、基础字段编辑、草稿保存、发布、封面选择、置顶/推荐开关等核心能力。编辑页已经从“后台表单”进入“可写作界面”的阶段，但整体仍偏传统管理后台，缺少主流文档编辑器常见的写作体验、预览能力、发布校验和内容工程化能力。

本需求文档目标是将当前文章编辑页升级为：

> 面向技术博客的 Markdown / MDX 写作工作台。

它不只是一个表单页，而应该支持从“写作 → 校验 → 预览 → 保存草稿 → 发布 → 查看发布结果”的完整内容生产链路。

---

## 2. 当前界面问题分析

### 2.1 信息架构问题

当前页面由左侧主编辑区和右侧发布设置区组成，方向正确，但存在以下问题：

1. 标题、slug、描述、内容、标签、封面、置顶、推荐、保存、发布都放在同一个页面，但缺少清晰的写作流程分区。
2. 右侧栏目前只是字段收纳区，没有形成真正的“发布控制面板”。
3. 顶部工具区只有返回、导出、导入，缺少预览、保存状态、自动保存状态、字数统计等编辑器核心信息。
4. 内容编辑区域只是普通 textarea，缺少 Markdown/MDX 工具栏、实时预览、快捷插入、错误提示和语法辅助。
5. 发布前没有质量检查，容易出现 slug 为空、description 为空、标签缺失、图片路径错误、正文格式异常等问题。
6. 成功提示位置较突兀，但缺少具体反馈，例如“草稿已保存”“发布任务已创建”“GitHub 提交成功”“Cloudflare 构建中”。

### 2.2 写作体验问题

当前编辑器更像“后台输入框”，而不是“文档编辑器”。主要不足：

1. 正文输入框高度固定，长文编辑不够舒适。
2. 没有 Markdown 快捷工具栏，例如标题、加粗、引用、代码块、链接、图片、表格、LaTeX。
3. 没有实时预览或分屏预览，技术文章中的代码块、LaTeX、MDX 组件无法即时检查。
4. 没有自动保存状态，用户不确定内容是否安全保存。
5. 没有快捷键提示，例如 `Ctrl/Cmd + S` 保存、`Ctrl/Cmd + Enter` 发布、`Ctrl/Cmd + P` 预览。
6. 没有文章结构辅助，例如目录提取、标题层级检查。

### 2.3 发布流程问题

当前右侧只有“保存草稿”和“发布”按钮，但发布在 Git-backed CMS 中不是一个简单动作。它可能包含：

1. 表单校验；
2. MDX 生成；
3. 内容校验；
4. GitHub 写入；
5. Git commit；
6. Cloudflare Pages 构建；
7. 前台可访问验证。

因此，发布按钮应该有明确的流程状态，而不是只显示一个普通按钮。

## 3. 设计参考原则

本编辑器可以参考以下主流编辑器的交互思想，但不直接照搬。

### 3.1 Notion 类编辑器

可借鉴点：

1. 写作空间干净，减少非必要干扰。
2. 块级内容组织清晰。
3. 支持快捷插入内容。
4. 编辑区优先，元信息弱化。

适用于本项目的改造：

* 提供沉浸写作模式；
* 提供 `/` 快捷插入菜单；
* 支持插入代码块、图片、引用、表格、LaTeX。

### 3.2 WordPress / Ghost 类 CMS

可借鉴点：

1. 左侧写作，右侧发布设置。
2. 发布前有状态、可见性、标签、封面、SEO 信息。
3. 支持草稿、预览、发布。
4. 发布后可查看文章链接。

适用于本项目的改造：

* 右侧栏升级为“发布面板”；
* 增加 SEO 面板、发布状态、文章链接、Git 提交状态；
* 增加发布前检查。

### 3.3 GitHub Markdown 编辑器

可借鉴点：

1. Markdown 工具栏直接有效。
2. Edit / Preview 双标签清晰。
3. 适合技术内容写作。
4. 对代码块、引用、列表、链接支持好。

适用于本项目的改造：

* 正文区域增加“编辑 / 预览 / 分屏”模式；
* 增加 Markdown 工具栏；
* 提供代码块语言选择；
* 提供 Markdown 语法辅助。

### 3.4 VS Code / Obsidian 类写作工具

可借鉴点：

1. 长文编辑体验好。
2. 支持快捷键。
3. 支持大纲、搜索、格式检查。
4. 适合技术笔记和 Markdown 写作。

适用于本项目的改造：

* 支持编辑器快捷键；
* 支持文档大纲；
* 支持查找替换；
* 支持内容校验面板。

## 4. 产品定位

### 4.1 页面定位

当前“新建文章”页面应升级为：

> 技术博客文章编辑工作台。

它需要同时满足：

1. 快速写作；
2. Markdown / MDX 编辑；
3. 元数据管理；
4. 内容质量检查；
5. 草稿保存；
6. Git-backed 发布；
7. 前台预览与发布确认。

### 4.2 用户角色

| 角色       | 使用目的          | 权限     |
| -------- | ------------- | ------ |
| 博主 / 管理员 | 写文章、发布文章、管理内容 | 全部权限   |
| 后续编辑者    | 编辑草稿、提交发布     | 可选后续版本 |

第一版仅考虑管理员单用户场景。

### 5.3 主编辑区

主编辑区分为两个卡片。

#### 5.3.1 基础信息卡片

字段：

1. 文章标题；
2. slug；
3. 描述；
4. 发布日期；
5. 文章类型。

建议：

* 标题输入后自动生成 slug；
* slug 支持手动编辑；
* description 显示字数限制；
* 日期默认今天；
* 文章类型默认“技术文章”。

#### 5.3.2 正文编辑卡片

正文编辑器应支持三种模式：

1. 编辑；
2. 预览；
3. 分屏。

顶部工具栏：

```text
H1 H2 H3 | B I | 引用 | 代码 | 链接 | 图片 | 表格 | LaTeX | MDX组件 | 撤销/重做
```

底部状态栏：

```text
字数：1234   阅读时间：6 min   标题数：8   代码块：3   图片：2
```

### 5.4 右侧发布面板

右侧栏应升级为多个折叠面板。

#### 5.4.1 发布面板

字段与按钮：

```text
状态：草稿
最后保存：14:32
最后发布：未发布

[保存草稿]
[预览文章]
[发布]
```

发布按钮状态：

| 状态   | 按钮表现       |
| ---- | ---------- |
| 可发布  | 蓝色主按钮      |
| 校验失败 | 禁用，提示先修复问题 |
| 发布中  | loading    |
| 发布失败 | 红色提示，支持重试  |
| 已发布  | 显示“重新发布”   |

#### 5.4.2 内容设置面板

字段：

1. 标签；
2. 封面图；
3. 置顶；
4. 推荐；
5. 阅读时间。

阅读时间建议自动计算，不允许手动编辑，或者默认自动计算、允许覆盖。

#### 5.4.3 SEO 面板

字段：

1. SEO 标题；
2. SEO 描述；
3. Canonical URL；
4. OpenGraph 图片。

第一版可只做展示与校验：

```text
SEO 描述：0 / 160
Canonical：自动生成
```

#### 5.4.4 内容校验面板

校验项：

* 标题已填写；
* slug 合法；
* slug 未重复；
* description 已填写；
* description 长度不超过 200；
* 正文不为空；
* 标签已填写；
* 图片路径有效；
* 代码块语言已填写；
* LaTeX 基础格式检查；
* MDX 组件白名单检查。

状态示例：

```text

✅ slug 合法
⚠️ description 为空
⚠️ 缺少标签
✅ 正文不为空
```

## 6. 功能需求

## 6.1 文章基础信息编辑

### 6.1.1 标题输入

用户故事：

> 作为博主，我希望输入文章标题后系统自动生成 slug，减少重复录入。

需求：

1. 标题为必填。
2. 标题输入后，若 slug 为空，自动生成 slug。
3. 若用户手动修改过 slug，则标题变化不再覆盖 slug。
4. 标题最大长度建议 100 字。
5. 标题为空时禁止发布。

验收标准：

* 输入“C# 和 Rust 哪个更适合做 CMS”，自动生成类似 `csharp-vs-rust-cms`。
* 用户手动修改 slug 后，再修改标题，不覆盖已有 slug。
* 标题为空时，发布按钮禁用或发布前校验失败。

### 6.1.2 Slug 编辑

需求：

1. slug 必填。
2. 只允许小写字母、数字、连字符。
3. 自动去除首尾连字符。
4. 自动将空格转换为连字符。
5. 保存前检查是否重复。
6. 提供复制按钮。

验收标准：

* `Hello World` 自动转换为 `hello-world`。
* 输入中文标题时，如果无法生成英文 slug，则提示用户手动填写。
* 重复 slug 显示错误：“该 slug 已存在”。

### 6.1.3 描述编辑

需求：

1. description 建议必填。
2. 最大长度 200 字。
3. 显示实时字数。
4. 超过限制时显示警告。
5. 可作为 SEO description 默认值。

验收标准：

* 字数实时显示 `120 / 200`。
* 超过 200 字显示红色提示。
* 发布前 description 为空时显示警告，但是否阻断发布可配置。

## 6.2 正文编辑器

### 6.2.1 编辑模式

需求：

1. 支持 Markdown / MDX 文本编辑。
2. 支持基础 Markdown 快捷按钮。
3. 支持快捷键：

    * `Ctrl/Cmd + S` 保存草稿；
    * `Ctrl/Cmd + Enter` 发布；
    * `Ctrl/Cmd + B` 加粗；
    * `Ctrl/Cmd + I` 斜体。
4. 支持 tab 缩进。
5. 支持自动保存光标位置。
6. 支持大文本输入不卡顿。

验收标准：

* 点击加粗按钮后，选中文本变成 `**文本**`。
* `Ctrl/Cmd + S` 能触发保存草稿。
* 输入 5000 字以上内容时无明显卡顿。

### 6.2.2 预览模式

需求：

1. 支持 Markdown 渲染。
2. 支持代码高亮。
3. 支持 GFM 表格、任务列表、删除线。
4. 支持 LaTeX 渲染。
5. 支持图片预览。
6. 支持基础 MDX 组件预览。

验收标准：

* `# 标题` 正确渲染为一级标题。
* 代码块正常高亮。
* `$x^2$` 可渲染为数学公式。
* 图片路径存在时正常显示，缺失时提示。

### 6.2.3 分屏模式

需求：

1. 左侧编辑，右侧预览。
2. 支持滚动同步。
3. 支持手动关闭预览。
4. 窄屏下自动切换为标签模式。

验收标准：

* 点击“分屏”后显示左右双栏。
* 编辑区滚动时，预览区大致同步。
* 屏幕宽度小于 1024px 时不强制双栏。

### 6.2.4 工具栏

第一版工具栏按钮：

1. 标题 H2；
2. 标题 H3；
3. 加粗；
4. 斜体；
5. 引用；
6. 无序列表；
7. 有序列表；
8. 代码块；
9. 链接；
10. 图片；
11. 表格；
12. LaTeX。

第二版可增加：

1. MDX 组件插入；
2. Mermaid 图；
3. Callout；
4. 目录锚点。

## 6.3 标签与分类

### 6.3.1 标签输入

需求：

1. 支持输入多个标签。
2. 支持已有标签联想。
3. 支持回车创建新标签。
4. 支持删除标签。
5. 支持转换为旧 frontmatter 格式。

验收标准：

* 输入 `Rust` 后回车生成一个标签。
* 输入时显示已有标签建议。
* 发布生成 MDX 时，能正确写入 frontmatter。

### 6.3.2 标签格式兼容

当前博客已有 `tag: "Go / Cache"` 格式。

建议短期兼容：

```yaml
tag: "Go / Cache"
```

中期可升级：

```yaml
tags:
  - Go
  - Cache
```

第一版建议保持现有格式，避免破坏前台。

## 6.4 封面图片

### 6.4.1 选择封面

需求：

1. 点击“选择封面”打开媒体选择器。
2. 支持从媒体库选择已有图片。
3. 支持上传新图片。
4. 支持预览封面。
5. 支持移除封面。

验收标准：

* 选择图片后右侧显示缩略图。
* 移除后恢复“无封面图片”。
* 上传非图片文件时提示错误。

### 6.4.2 图片安全与规范

需求：

1. 仅允许 jpg、jpeg、png、webp、gif。
2. 单文件大小限制，例如 5MB。
3. 文件名自动 slug 化。
4. 上传后存储到约定目录。
5. 可选：自动生成 webp。

## 6.5 草稿保存

### 6.5.1 手动保存草稿

需求：

1. 点击“保存草稿”保存当前内容。
2. 保存成功显示明确提示。
3. 保存失败显示错误原因。
4. 保存时按钮 loading。
5. 保存后更新最后保存时间。

验收标准：

* 点击保存后出现“保存中”。
* 成功后显示“草稿已保存”。
* 网络失败时显示“保存失败，请重试”。

### 6.5.2 自动保存

建议第二版实现。

需求：

1. 用户停止输入 3 秒后自动保存。
2. 自动保存不触发发布。
3. 显示自动保存状态。
4. 避免频繁请求。

状态文案：

```text
未保存
保存中...
已保存于 14:32
保存失败
```

## 6.6 发布流程

### 6.6.1 发布前校验

发布前必须执行：

1. 标题校验；
2. slug 校验；
3. description 校验；
4. 正文非空校验；
5. 标签校验；
6. frontmatter 生成校验；
7. MDX 基础语法校验；
8. Git 写入权限校验。

校验分级：

| 级别      | 行为         |
| ------- | ---------- |
| Error   | 阻断发布       |
| Warning | 允许发布，但需要确认 |
| Info    | 仅提示        |

### 6.6.2 发布动作

发布流程：

```text
点击发布
→ 前端校验
→ 后端创建发布任务
→ 生成 MDX
→ 写入 GitHub
→ 记录 commit sha
→ 返回发布结果
→ 可选查询 Cloudflare 构建状态
```

发布状态：

```text
Draft
Publishing
Published
PublishFailed
```

### 6.6.3 发布结果反馈

发布成功时显示：

```text
发布成功
Commit: abc1234
前台链接：https://shuhong.icu/posts/xxx
[打开文章] [复制链接]
```

发布失败时显示：

```text
发布失败
原因：GitHub 写入失败 / slug 冲突 / token 权限不足
[重试发布] [查看详情]
```

## 6.7 导入与导出

### 6.7.1 导出

当前已有导出按钮，建议明确导出格式。

需求：

1. 导出当前文章为 `.mdx`。
2. 导出时包含 frontmatter。
3. 文件名使用 slug。
4. slug 为空时禁止导出或使用临时文件名。

验收标准：

* 点击导出后下载 `article-slug.mdx`。
* 文件内容包含 frontmatter 和正文。

### 6.7.2 导入

需求：

1. 支持导入 `.md` / `.mdx` 文件。
2. 自动解析 frontmatter。
3. 将解析结果填充到标题、description、tag、date、正文。
4. 解析失败时显示错误详情。
5. 导入后默认保存为草稿。

验收标准：

* 导入现有 MDX 文件后，标题、描述、正文正确回填。
* frontmatter 缺字段时显示警告。

## 6.8 预览功能

### 6.8.1 编辑器内预览

见 6.2。

### 6.8.2 前台样式预览

建议第二版实现。

需求：

1. 点击“预览文章”打开新窗口。
2. 使用与博客前台一致的样式。
3. 未发布文章也可预览。
4. 预览链接有短期有效期或仅管理员可访问。

验收标准：

* 未发布草稿可以预览。
* 预览效果接近前台文章详情页。

---

## 7. 非功能需求

### 7.1 性能

1. 编辑器输入延迟应小于 100ms。
2. 文章内容 10,000 字以内应流畅编辑。
3. 预览渲染应防抖，避免每个字符都完整重渲染。
4. 保存草稿接口响应建议小于 500ms。

### 7.2 可用性

1. 页面刷新前如有未保存内容，应提示。
2. 保存失败时不得丢失本地输入。
3. 发布失败时保留草稿。
4. 长文章编辑时应支持滚动恢复。

### 7.3 安全

1. 后台 API 必须鉴权。
2. 上传文件必须限制类型和大小。
3. MDX 渲染必须避免危险脚本。
4. GitHub Token 只能存在后端环境变量或部署平台 Secret 中。
5. 前端不得出现任何 GitHub Token。
6. 发布接口需要防重复提交。

### 7.4 兼容性

1. 桌面优先，兼容 1366px 以上宽度。
2. 平板宽度下右侧栏可折叠。
3. 手机端第一版可只保证基本可用，不作为主要写作场景。

## 8. API 需求建议

### 8.1 草稿保存

```http
POST /api/articles/draft
```

请求：

```json
{
  "id": 1,
  "title": "文章标题",
  "slug": "article-slug",
  "description": "文章描述",
  "content": "# 正文",
  "tag": "Rust / CMS",
  "coverImageUrl": "/images/cover.webp",
  "isTop": false,
  "isFeatured": false
}
```

响应：

```json
{
  "success": true,
  "articleId": 1,
  "savedAt": "2026-05-09T12:30:00Z"
}
```

### 8.2 文章校验

```http
POST /api/articles/validate
```

响应：

```json
{
  "valid": false,
  "errors": [
    {
      "code": "SLUG_REQUIRED",
      "message": "slug 不能为空",
      "field": "slug"
    }
  ],
  "warnings": [
    {
      "code": "DESCRIPTION_EMPTY",
      "message": "建议填写文章描述",
      "field": "description"
    }
  ]
}
```

### 8.3 发布文章

```http
POST /api/articles/{id}/publish
```

响应：

```json
{
  "success": true,
  "jobId": "job_123",
  "status": "Publishing"
}
```

### 8.4 查询发布任务

```http
GET /api/publish-jobs/{jobId}
```

响应：

```json
{
  "jobId": "job_123",
  "status": "Succeeded",
  "commitSha": "abc1234",
  "publicUrl": "https://shuhong.icu/posts/article-slug",
  "errorMessage": null
}
```
