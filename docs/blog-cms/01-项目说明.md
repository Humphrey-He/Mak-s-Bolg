# 博客自研 CMS 项目说明

## 一、项目背景

### 1.1 现状分析

当前博客技术栈：
- **前台**：Next.js 静态导出 + Cloudflare Pages
- **内容**：MDX 格式存储于 Git 仓库
- **内容管理**：TinaCMS（Git-backed CMS）

TinaCMS 的局限性：
- 依赖第三方服务（Tina Cloud）
- 分支索引偶发故障
- 自定义能力受限
- 团队协作功能有限

### 1.2 建设目标

构建一套自有的博客内容管理系统，实现：
- 独立可控的内容管理能力
- 高效的内容创作与发布体验
- 可扩展的架构设计
- 技术作品展示价值

### 1.3 建设原则

1. **最小可用**：快速上线 MVP，持续迭代
2. **技术变现**：C# 练手 + Rust 内容引擎形成技术亮点
3. **渐进迁移**：不影响现有博客运行，逐步替代 TinaCMS
4. **数据源单一**：明确 Git/MDX 为权威源，避免双主数据源

---

## 二、数据权威源约定

> **核心原则：Git/MDX 是内容权威源，数据库只做后台索引和草稿管理。**

```
┌─────────────────────────────────────────────────────────────────┐
│                         权威数据源                               │
│                                                                 │
│   Git 仓库 content/posts/*.mdx  ←  唯一权威来源                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
                              ↑
                    发布时写入 / 构建时读取
                              │
┌─────────────────────────────────────────────────────────────────┐
│                         CMS 数据库                               │
│                                                                 │
│   仅保存：草稿、发布任务、媒体索引、操作记录                      │
│   不保存：已发布的文章内容（内容以 MDX 为准）                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.1 数据流向

```
草稿阶段：
CMS 数据库保存 draft 内容
    ↓ 用户点击发布
CMS 生成/更新 MDX 文件
    ↓
提交到 GitHub
    ↓
Cloudflare Pages 自动构建
    ↓
前台展示（读取 Git 中的 MDX）

正式线上内容：
以 Git 仓库里的 MDX 为准
CMS 数据库仅作索引和状态追踪
```

### 2.2 数据库与 Git 的职责划分

| 存储位置 | 职责 | 说明 |
|---------|-----|-----|
| Git/MDX | 正式发布内容 | 唯一权威源 |
| Git/MDX | 前台构建 | Cloudflare Pages 静态生成 |
| CMS 数据库 | 草稿内容 | 未发布状态 |
| CMS 数据库 | 发布任务 | 任务队列和状态追踪 |
| CMS 数据库 | 媒体索引 | 文件 URL 和元数据 |
| CMS 数据库 | 操作日志 | 审计追踪 |

### 2.3 冲突处理原则

| 场景 | 处理方式 |
|-----|---------|
| GitHub 手动修改 MDX | 数据库同步读取 Git，数据库草稿覆盖 |
| Git push 失败 | 发布任务标记 Failed，数据库回滚草稿状态 |
| 数据库草稿 vs 线上 MDX | 以 Git/MDX 为准（用户需重新发布草稿） |
| slug 改名 | 旧 MDX 文件删除 + 新 MDX 创建 |

## 三、系统边界

```
┌────────────────────────────────────────────────────────────────────────┐
│                           用户视角                                      │
│                                                                        │
│  ┌─────────────┐     ┌─────────────┐     ┌─────────────┐            │
│  │   博客前台   │     │   CMS 后台   │     │  Rust 引擎  │            │
│  │ (Cloudflare)│     │  (C# ASP.NET)│     │   (CLI)     │            │
│  │  静态站点    │     │  管理/认证   │     │ 内容工具链   │            │
│  └──────┬──────┘     └──────┬──────┘     └─────────────┘            │
│         │                    │                                        │
│         │ 静态构建            │ 发布写入                                 │
│         ↓                    ↓                                        │
│  ┌──────────────────────────────────────────────┐                    │
│  │              Git 仓库 (权威源)                 │                    │
│  │        content/posts/*.mdx                    │                    │
│  └──────────────────────────────────────────────┘                    │
└────────────────────────────────────────────────────────────────────────┘

读者访问：Cloudflare Pages → 静态博客（无感知）
作者管理：CMS Admin → C# API → 生成 MDX → GitHub → Cloudflare Pages
```

## 五、建设内容（按阶段）

### Phase 0：准备期（1 周）

**目标：理顺内容结构和发布机制，不影响现有博客**

- 固定 MDX frontmatter schema
- 写内容校验脚本
- 统一 slug/date/tag/readTime 规则
- Cloudflare Pages 部署稳定
- Tina 继续作为临时后台或手动 GitHub 编辑

### Phase 1：CMS MVP（3-4 周）

**目标：替代 Tina 的核心写作发布链路**

| 模块 | 功能点 |
|-----|-------|
| 认证管理 | 登录/JWT/会话管理 |
| 文章管理 | 列表/新建/编辑/草稿保存 |
| 内容发布 | MDX 生成/GitHub push |
| 发布追踪 | 发布任务状态/失败重试 |
| 管理后台 | React Admin 基础 UI |

### Phase 2：后台增强（3-4 周）

**目标：完善内容管理能力**

| 模块 | 功能点 |
|-----|-------|
| 媒体库 | 图片上传/管理/插入 |
| 标签管理 | 标签 CRUD |
| 文章预览 | 发布前预览效果 |
| 操作日志 | 审计追踪 |
| SEO 工具 | Sitemap/RSS 生成 |

### Phase 3：Rust 内容引擎（3-5 周）

**目标：高性能内容处理工具链**

| 模块 | 功能点 |
|-----|-------|
| CLI 工具 | validate/index/generate 命令 |
| 内容校验 | MDX frontmatter 校验 |
| 搜索索引 | Tantivy 索引构建 |
| SEO 生成 | Sitemap/RSS |

### Phase 4：生产稳定化（1-2 周）

**目标：生产环境可用**

- 数据库迁移（SQLite → PostgreSQL）
- 部署上线
- TinaCMS 停用
