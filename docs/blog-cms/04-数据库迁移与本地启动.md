# BlogCMS 数据库迁移与本地启动

## 这份文档解决什么问题

BlogCMS 的管理后台分成两部分：

- `BlogCMS.Admin`：前端，默认端口 `3002`
- `BlogCMS.Api`：后端，默认端口 `5000`

前端保存文章时实际调用的是 `http://localhost:3002/api/...`，再由 Vite 代理到 `http://localhost:5000/api/...`。

如果前端还开着、后端没启动，浏览器里经常会看到：

- `保存失败: Request failed with status code 500`

这类报错不一定代表保存逻辑坏了，很多时候只是后端 API 没有在监听。

## 这次修复了什么

之前数据库和代码模型出现了漂移，导致：

- `GET /api/tags` 因为缺少 `Tags` 表返回 `500`
- 文章读取和保存因为缺少 `Articles.CoverImageUrl` 列返回 `500`

现在 `BlogCMS.Api` 已经改成启动时自动执行迁移，不再只靠 `EnsureCreated()`。

迁移入口：

- `src/BlogCMS.Api/Program.cs`

迁移实现：

- `src/BlogCMS.Api/Data/BlogDbMigrator.cs`

## 当前迁移机制

系统会在 SQLite 数据库里维护一张迁移版本表：

- `__BlogSchemaMigrations`

目前已经包含的迁移：

1. `0001_initial_cms_schema`
   - 创建 `Admins`
   - 创建 `Articles`
   - 创建 `PublishJobs`
   - 创建 `Media`
   - 创建核心索引

2. `0002_tags_schema`
   - 创建 `Tags`
   - 创建 `Tags.Slug` 唯一索引

3. `0003_article_cover_fields`
   - 补齐 `Articles.CoverImageId`
   - 补齐 `Articles.CoverImageUrl`

这个迁移器是幂等的：

- 新库可以直接初始化
- 旧库会自动补缺的表和列
- 不需要手工删库重建

## 本地开发正确启动方式

### 方式 1：直接用脚本

推荐先运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-blogcms-dev.ps1
```

这个脚本会：

1. 检查 `5000` 端口是否已有 `BlogCMS.Api`
2. 如果没有，就启动后端
3. 检查 `3002` 端口是否已有 `BlogCMS.Admin`
4. 如果没有，就启动前端

单独启动 API：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-blogcms-api.ps1
```

### 方式 2：手工分别启动

启动后端：

```powershell
cd .\src\BlogCMS.Api
dotnet run --urls "http://0.0.0.0:5000"
```

启动前端：

```powershell
cd .\src\BlogCMS.Admin
npm run dev
```

## 启动后如何自检

### 端口检查

- 前端：admin `http://localhost:3002`
- 后端：api `http://localhost:5000`

### 最低限度的接口检查

先登录拿 token，再检查：

- `POST /api/auth/login`
- `GET /api/tags`
- `GET /api/articles`

如果这些接口正常，文章保存链路基本就通了。

## 默认本地管理员

如果是本地默认 seed 数据库：

- 用户名：`admin`
- 密码：`admin123`

如果你已经手工改过数据库内容，请以你当前数据库里的账号为准。

## 再次出现“保存失败 500”时先看什么

按这个顺序排查：

1. `5000` 端口的 API 是否在监听
2. `BlogCMS.Api` 日志里是否有新的 SQLite 报错
3. 当前请求是不是命中了唯一约束，例如重复 `slug`
4. 前端是否已经登录并带上 token

如果 `3002` 正常、`5000` 没起来，浏览器通常会把这个问题表现成保存失败，但根因其实是后端没启动。
