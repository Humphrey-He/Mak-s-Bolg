# 博客新功能与改进建议

更新日期：2026-05-08

适用仓库：
- `E:\awesomeProject\Mak's Blog\Mak-s-Bolg-remote`

分析基线：
- 当前站点已经具备首页、文章流、项目页、Agent 页、后端专题页、关于页、留言页
- 当前视觉方向明确，具备赛博技术博客辨识度
- 已完成一轮构建检查与真实浏览器检查

## 1. 当前项目的优势

这个博客已经有几件很好的基础：

- 视觉方向清晰
  现在的深色网格、扫描线、霓虹边框、代码感卡片已经形成了“技术个人品牌”。

- 内容主题聚焦
  后端工程、云原生、网关、缓存、对象存储、AI Agent 这些主题是连贯的，不是杂谈式博客。

- 首页已经具备内容编排意识
  不是单纯把文章列表堆出来，而是加入了 Hero、Agent 区、人格区、后端专题区，已经有“数字花园”的雏形。

- 数据结构已经为内容站升级留了口子
  `posts.ts`、`projects.ts`、`backend.ts`、`readings.ts` 已经能支持后续演进到详情页、CMS、API 接入。

## 2. 当前最值得优先改善的问题

这些问题不会否定项目方向，但它们会直接影响第一次访问体验。

### P0：先把“真实可用性”收口

当前浏览器实测里，最优先的不是加新模块，而是把两个体验阻塞点修透：

- 移动端导航断点行为不稳定
- Blog 顶部 Top 5 焦点区按钮显示了，但切换没有真正生效

原因：
- 这两个问题都发生在用户最容易接触到的区域
- 会直接影响“这个站能不能顺畅用”的第一印象

建议：
- 先把首页和 `/blog` 的桌面端、移动端交互都验收通过
- 再进入新功能开发

### P0：首页还缺少一个“内容入口层级”

现在首页已经有内容，但还不够“好逛”：

- 用户知道你是谁
- 也知道你写什么
- 但不够清楚“我应该从哪里开始读”

建议补一个首页入口层：
- 新手入口：适合第一次来的读者
- 主题入口：缓存 / 网关 / 云原生 / Agent
- 连载入口：源码拆解、系统设计、项目复盘

这样首页会从“展示页”变成“阅读入口页”。

### P1：博客还是“列表站”，还不是“内容站”

现在最明显的结构性短板是：

- 没有 `blog/[slug]`
- 没有文章详情页
- 没有项目详情页
- 没有系列阅读关系

这意味着：
- 当前更像一个作品展示原型
- 还不像一个可以长期积累内容的博客系统

## 3. 最适合这个博客的新功能方向

下面这些不是泛泛而谈的“常见博客功能”，而是更贴合你这个博客定位的方向。

### 方向 A：专题式阅读入口

推荐新增：
- 技术专题页
- 系列文章页
- 路线图式阅读页

适合的专题：
- Go 缓存系统
- APISIX / 网关插件
- Kubernetes 与云原生工程
- AI Agent 工程化
- 对象存储 / COS / S3 能力实现

为什么值得做：
- 你的内容天然适合专题化，不适合只按时间倒序展示
- 专题能提高停留时长，也更利于形成个人方法论

推荐落点：
- `app/topics/page.tsx`
- `app/topics/[slug]/page.tsx`
- `data/topics.ts`

### 方向 B：文章详情页 + 阅读辅助系统

推荐新增：
- 文章详情页
- 目录导航
- 阅读进度
- 相关文章推荐
- “继续阅读”模块

为什么值得做：
- 现在站点最缺的是“读进去”的能力
- 详情页建立起来后，文章列表、精选、专题、推荐才真正串得起来

推荐落点：
- `app/blog/[slug]/page.tsx`
- `components/blog/PostToc.tsx`
- `components/blog/RelatedPosts.tsx`
- `components/blog/ContinueReading.tsx`

### 方向 C：项目页升级成“工程档案馆”

当前项目页更像卡片墙，建议升级成“工程档案馆”：

推荐新增字段：
- 项目背景
- 技术栈
- 架构图
- 核心问题
- 关键权衡
- 踩坑记录
- 演进路线

为什么值得做：
- 这类内容最能体现你的技术深度
- 比单纯展示“做过什么”更有说服力

推荐落点：
- `app/projects/[slug]/page.tsx`
- `data/projects.ts` 增加 `slug`、`summary`、`sections`

### 方向 D：Agent 区做成“实验室”而不只是介绍页

这是这个博客最有特色的差异化方向之一。

推荐新增：
- Tool Calling Timeline
- Memory Capsule 面板
- Prompt / Planning 过程可视化
- Risk Control 开关
- Agent 实验日志

为什么值得做：
- Agent 内容本来就适合“过程可视化”
- 这会把 `/agent` 从说明页升级成站点的代表性页面

推荐落点：
- `components/agent/AgentTimeline.tsx`
- `components/agent/AgentMemoryCapsules.tsx`
- `components/agent/AgentRiskControls.tsx`
- `components/agent/AgentExperimentLog.tsx`

### 方向 E：最近阅读与知识流

你现在已经有 `recentReadings` 数据，这很适合扩成“知识流”。

推荐新增：
- 最近阅读页
- 书籍 / 论文 / 开源项目分类
- 阅读状态
- 摘录卡片
- “这篇内容影响了哪些文章” 的反向关联

为什么值得做：
- 这能把博客从“输出内容”升级成“思考轨迹”
- 对技术博客来说，这类内容很容易建立长期粘性

推荐落点：
- `app/readings/page.tsx`
- `components/readings/ReadingTimeline.tsx`
- `components/readings/ReadingNoteCard.tsx`

### 方向 F：留言页升级成真实互动页

当前留言页还是静态壳，建议别只做“表单”。

推荐新增：
- 联系意图分类
- 留言成功状态
- 预期回复方式说明
- 友链 / 合作 / 技术交流分类入口

进阶版可以接：
- GitHub Issues
- 自建 API
- 邮件通知
- 轻量评论系统

为什么值得做：
- 对个人博客来说，留言页是“把浏览转成联系”的关键页面

## 4. 高回报的小改进

这些不是大功能，但投入小、提升明显。

### 4.1 首页增加“从这里开始”

在 Hero 下方补一个小模块：
- 第一次来：推荐读这 3 篇
- 想看项目：从这里进入
- 想看 Agent：从实验室开始

价值：
- 降低第一次访问的选择成本

### 4.2 增加文章状态标签

例如：
- 精选
- 连载
- 复盘
- 源码拆解
- 系统设计

价值：
- 比按日期更能表达内容属性

### 4.3 增加站内搜索反馈层

当前搜索有输入框，但可以继续增强：
- 热门关键词
- 空结果建议
- 搜索历史
- 主题过滤

### 4.4 增加“最近更新”区

在首页和 `/blog` 页加入：
- 最近发布
- 最近更新
- 本周精选

价值：
- 强化博客“持续在生长”的感觉

### 4.5 增加状态型页脚

推荐加入：
- 当前专注主题
- 最近在读
- 当前折腾项目
- 仓库链接
- RSS / 邮件订阅

这会让博客更像一个“持续在线的个人技术空间”。

## 5. 适合你的差异化亮点

如果只做通用博客功能，这个项目会变普通。更建议强化下面几种差异化：

### 5.1 工程化叙事

每篇文章不只是讲概念，而是尽量围绕：
- 问题是什么
- 为什么这么设计
- 做过哪些权衡
- 哪些地方踩过坑
- 最终方案如何演进

这会比“知识点型博客”更有记忆点。

### 5.2 源码拆解路线

适合你现在主题的固定栏目：
- APISIX 插件源码拆解
- Go 缓存系统设计拆解
- Agent 框架运行链路拆解
- 云原生组件升级 / 回滚设计拆解

建议做成系列，而不是散文式文章。

### 5.3 技术人格化入口

你已经有 `PersonaLab`，这是很好的想法。

可以继续扩成：
- 夜行 Debugger：问题排查类内容
- 系统架构航海家：设计与拆解类内容
- 缓存命中猎人：性能与缓存类内容
- Agent 召唤师：Agent 实验类内容

这会让站点有更强的风格识别度。

## 6. 推荐实施顺序

### 第一阶段：先修可用性

- 修移动端导航断点
- 修 Blog Top 5 切换真实生效
- 再做一轮桌面端 / 移动端浏览器复检

### 第二阶段：把博客升级成内容站

- 建 `blog/[slug]`
- 建 `projects/[slug]`
- 增加文章详情页结构
- 增加项目详情页结构

### 第三阶段：加强首页导流

- 增加“从这里开始”
- 增加主题入口
- 增加最近更新 / 最近阅读

### 第四阶段：做出差异化亮点

- 强化 Agent 实验室
- 强化专题阅读页
- 强化知识流 / 最近阅读

## 7. 最推荐你先做的三件事

如果只选三件，推荐优先做：

1. 修完首页和 `/blog` 的真实交互问题
2. 开始做 `blog/[slug]` 文章详情页
3. 给首页增加“从这里开始”和专题入口

原因：
- 第一件解决基础可信度
- 第二件让它真正成为博客
- 第三件提升第一次访问体验
